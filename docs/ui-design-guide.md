# 赛道时刻 · 界面设计手册

## 适用基线

以 2026-10-11 恢复后的 main 快照 b3d3679、线上 v2.2.2 为基线。已核对首页的实际页面结构，以及 globals.css、schedule-view、event-card、week-view、month-view、usage-guide 的实现。

本手册约束后续设计，不表示每条规范都已在旧组件中实现。标为“现有”的内容是当前基线；标为“新增规则”的内容用于后续新增或修改。小功能建议单独列出，不代表实施授权。

## 1. 设计定位与信息优先级

中文赛车赛程工具，暗色、克制、方便扫读。视觉服务于“什么比赛、什么时候、怎么看”。

- 第一层：赛事名称、北京时间、下一场次、进行状态。
- 第二层：系列、轮次、地点、转播信息、展开和详情入口。
- 第三层：来源、估计说明、客户端补充来源、天气及历史信息。
- 新增规则：辅助信息默认收起，不能为了新功能把首屏变成设置面板。
- 新增规则：每项小功能优先融入现有控件；新增独立区块前说明为什么现有位置不足。
- 不使用 emoji 作为界面图标；沿用 lucide-react。正式赛历不引入实验性特效，Playground 用于独立探索。

## 2. 页面结构与间距

现有首页顺序：标题与北京时间 → 数据来源 → 搜索和筛选 → 下一站预览 → 赛程视图 → 反馈 → 底部胶囊入口 → 时间说明。

| 项目 | 现有基线 / 后续规则 |
| --- | --- |
| 首页内容宽度 | `max-w-3xl`，48rem；居中，不随大屏无限拉宽 |
| 手机左右留白 | 16px，沿用 `px-4` |
| 页面上下留白 | 手机 32px，sm 起 40px |
| 大区块间距 | 24px，沿用 `gap-6` |
| 列表卡片间距 | 12px，沿用 `gap-3` |
| 卡片内边距 | 默认 16px；需要更宽松时桌面 20px |
| 紧密元素间距 | 4 / 6 / 8px；分组间距 12 / 16px |

新增规则：采用 4px 间距刻度，6px 仅用于紧凑图文组合。不要嵌套多层同样的边框卡片；一个区域最多有主容器和内部信息分组两层。

## 3. 颜色与材质

使用 `app/globals.css` 的语义变量，禁止为新组件另造一套灰色主题。

| 用途 | 变量及当前值 |
| --- | --- |
| 页面背景 | `--background: oklch(0.145 0 0)` |
| 卡片与弹层 | `--card` / `--popover: oklch(0.205 0 0)` |
| 次级表面 | `--secondary` / `--muted: oklch(0.269 0 0)` |
| 主要文字 | `--foreground: oklch(0.985 0 0)` |
| 次要文字 | `--muted-foreground: oklch(0.708 0 0)` |
| 主按钮 | `--primary: oklch(0.92 0 0)`，配 primary-foreground |
| 边框 | `--border: oklch(1 0 0 / 10%)` |
| F1 / WRC / FE | `--f1: oklch(0.62 0.23 25)` / `--wrc: oklch(0.6 0.16 250)` / `--fe: oklch(0.72 0.16 165)` |

系列颜色只用于识别系列、少量标记及相关强调，实际徽章沿用 SERIES_META，避免 CSS 变量与元数据各自演化。LIVE 红色表示正在进行；警告使用琥珀色；失败使用 destructive。必须同时提供文字或图标，不只依赖颜色。

现有卡片：低对比边框、轻阴影，悬停略提高边框和阴影。新增规则：常规页面不增加大面积渐变、发光、玻璃模糊或装饰纹理。

## 4. 字体、字号与数字

正文沿用 Geist Sans 与系统中文回退；时间、倒计时使用 font-mono 和 tabular-nums，减少数字更新导致的跳动。

| 层级 | 基线 |
| --- | --- |
| 页面标题 | 手机 24px / 桌面 30px，bold |
| 赛事卡片标题 | 16px，semibold |
| 正文与地点 | 14px |
| 按钮、标签、说明 | 12px |
| 数据来源及页脚 | 11px，仅用于辅助信息 |
| 微型装饰标签 | 10px，仅用于非关键状态 |

新增规则：关键开赛时间至少 14px；不要靠放大所有标题制造层级。长赛事名在紧凑卡片可省略，但详情页必须完整呈现。截断不能导致时间、主要操作或状态消失。

## 5. 圆角与图标

现有基础 radius 为 0.7rem；卡片 rounded-xl，输入与系列徽章 rounded-lg，视图切换 rounded-md，底部入口 rounded-full。按角色复用，不能每个控件各用一种圆角。

图标通常 14–16px，空态图标可 32–40px；与文字间距 6px。装饰图标 aria-hidden；只有图标的按钮必须有中文 aria-label。新增规则：手机主要点击热区至少 44×44px，图标本身保持小尺寸。

## 6. 赛事卡片

现有摘要由系列与轮次、名称与地点、开赛时间与倒计时组成；底部条放转播信息、来源、详情和展开入口。手机纵向排列，sm 起按列对齐。

- 新增规则：新操作进入卡片底部操作区域，或进入已展开的详情区，不能挤占标题与时间。
- 收藏等状态操作保留明确的选中样式和可访问名称。
- “详细”负责展开卡片，“详情”负责进入页面；不要合并两种行为。
- 不把含有多个按钮和链接的整张卡片包成一个可点击链接。
- 展开后按日期组织场次；北京时间保持主视图，当地时间明确标出时区。
- 估计赛段不能展示为已确认的精确时间。来源 i 提示必须支持点击，不能只靠 hover。
- 新增规则：从卡片进入详情再返回时，尽量保留用户原来的视图、筛选和滚动位置。

## 7. 筛选、视图及底部入口

搜索优先；系列与时间范围采用当前分组按钮；复杂条件放高级筛选。已选项必须有明确样式，相关分组提供 tablist/tab 或合适的按压状态。

周/月视图以日期为主；格子只显示简要赛事信息，完整场次在选中日期的下方详情区呈现。新增规则：同日多赛事不得无限堆高格子，可采用“另有 N 场”；同时保留访问完整信息的路径。

底部胶囊保持低强调、小图标和短文字，用于积分榜、历史赛果、壁纸、赛道数据库、版本、指南及开发者信息。不要把新主要功能全部塞进胶囊。反馈按钮保留现有“提建议 / 报 Bug”文案和位置，便于用户寻找。

## 8. 动效规则（新增规则）

| 场景 | 推荐时长与行为 |
| --- | --- |
| 悬停、按压、选中 | 120–180ms，颜色/透明度变化 |
| 小开关、图标切换 | 180–240ms，轻微位移或淡入淡出 |
| 卡片展开、弹层 | 200–280ms，ease-out，位移不超过 8px |
| 视图内容切换 | 180–240ms，轻淡入，保持容器稳定 |

- 同一动作只保留一个主要动效，不同时做弹跳、旋转、缩放和发光。
- 优先 transition-opacity、transition-transform 或 transition-colors；不要默认 transition-all。
- 常规开关禁止弹簧过冲；倒计时不得每秒引发整张卡片抖动或重新入场。
- LIVE 的局部脉冲可以保留，不能扩散到整页。
- 支持 prefers-reduced-motion：关闭装饰位移、连续脉冲与数字滚动，状态变化仍然清楚。
- 若未来重新设计防剧透：首屏即保护真实数据，先隐藏敏感内容再播放过渡；不能使用模糊层遮盖仍可读或仍可被辅助技术访问的成绩。主动揭晓后才呈现内容，不能自动揭晓。

## 9. 弹层、提示与指南

普通弹层沿用 bg-card、border-border 和 rounded-xl/2xl；遮罩用于聚焦，不以透明装饰牺牲可读性。支持 Esc 关闭、焦点限制、关闭后焦点回到触发按钮。

指南沿用实际目标框选和旁边说明的方式：入口先选择界面，卡片演示定位首页最上面的真实赛事卡片。避免凭空造示例卡片；找不到目标时给出可理解的替代提示。一次解释一个动作，说明控制在 2–3 句；允许跳过和从底部手动重开。

新增规则：复制等轻操作在按钮旁反馈“已复制”，1.5–2 秒恢复；错误反馈保留至下一次操作，不用自动消失的弹窗隐藏失败原因。成功反馈不能提前于实际动作成功。

## 10. 状态与中文文案

- 加载：骨架保持最终卡片结构，减少布局跳动。
- 无匹配：说明当前筛选无结果，提供重置；不要伪装为网络失败。
- 网络失败：说明无法更新，提供重试；旧缓存可以继续显示，但标记离线和可能过期。
- 未确认：写“时间待确认”或“赛程待定”，不伪造官方精确时间。
- 客户端补充：保留来源、上传时间和待核验含义。
- 不可操作：禁用样式之外，还应提供简短原因。
- 文案用动作词：“复制赛程”“清除筛选”“返回本周”；同一行为保持同一名称。
- 不在用户流程里解释接口、数据库、缓存锁等实现细节。

## 11. 每次 UI 修改的验收

1. 检查手机 375/390px 与桌面，必要时检查 320px、200% 缩放；页面无意外横向溢出。
2. 检查长名称、多场次、缺少图片、无数据、加载、失败和离线状态。
3. 验证 Tab / Enter / Space / Esc 与焦点回归，hover 功能在触屏也能完成。
4. 检查正常动效和减少动态效果设置；不遮住时间与操作，不因切换出现闪烁。
5. 关键文字保持可读；常规文字目标对比度至少 4.5:1，不能仅靠色彩传达状态。
6. 下载、复制等操作验证实际结果；有新增状态时验证刷新与返回行为。
7. 先在 Playground 比较复杂动效，再移入正式组件；不得引入实验入口或噪声干扰首页。
8. 完整类型检查与构建按项目约定分别报告；线上效果需实际页面检查。

## 12. 可优先考虑的小功能（尚未实施）

| 建议 | 位置与交互 | 范围 |
| --- | --- | --- |
| 复制一场赛程 | 卡片展开区或详情页，一键复制名称、北京时间、场次与站点链接；旁边反馈已复制 | 客户端；待确认场次不输出精确时间 |
| 一键收起已展开卡片 | 列表标题右侧，仅有卡片展开时显示 | 客户端；不增加常驻工具栏 |
| 返回时保留筛选和位置 | 详情页返回赛历，恢复用户离开前的状态 | 客户端会话内；直接访问首页保持默认 |
| 日期快捷定位 | 周/月视图小按钮“下一场”，跳到下一场已知赛事日期 | 复用已有赛程，不新增数据源 |
| 当前筛选摘要 | 搜索/高级筛选启用时出现“亚洲 · 街道赛道”等小标签，标签可逐项移除 | 复用现有筛选，不再增加一层筛选体系 |

建议按一个小功能一轮开发和验收推进；涉及时间、数据来源或权限的功能不能因为 UI 简单而省略数据验证。
