# 当前数据获取逻辑

本文根据 dev/data-pipeline 分支当前实现整理，描述实际实现，不代表已验证生产环境变量、数据库内容或上游接口可用性。

F1 起跑状态由独立 `/api/f1-start` 获取，使用无账号 SignalR Core 有限快照，只订阅场次、赛事控制与圈数。它不参与赛历持久化；不上报、不写数据库；每次连接受 7 秒总截止时间限制并关闭，同一运行实例共享 8 秒缓存与并发请求。客户端仅在沉浸式正赛倒计时开赛前 30 分钟至开赛后 10 分钟、页面可见时非重叠轮询。响应 `no-store`，不能进入浏览器、离线或 SW 缓存。场次与目标 UTC 不匹配、陈旧消息、上游失败均返回 unknown，不把旧比赛快照当实时状态。赛程灯光与实时状态的区别见 `docs/immersive-countdown.md`。

## 1. 主赛历入口

`/api/schedule` 使用 `connection()` 限定运行时获取，构建不会预抓取赛季。`app/page.tsx` 只提供服务器时间给 `ScheduleView`，没有服务端预取赛历。首页客户端通过 SWR 请求 `GET /api/schedule`。SWR 关闭焦点刷新，没有设置定时轮询；每秒更新的是倒计时，不是赛历数据。

首页 fetcher 将每个 `ok=true` 且含有赛事的系列分别保存在 localStorage 的 `schedule-cache-v2` 中。接口返回 200 但某系列失败或没有赛事时，不会用失败/估算结果覆盖该系列的成功缓存；页面用本机该系列最近一次成功数据补齐，并在来源栏以“本机缓存”和悬浮说明标出缓存时间及本次获取状态。其他成功系列仍正常更新。网络错误或非 2xx 时，从各系列缓存组合页面数据并增加 `offline=true`。旧版完整响应缓存只迁移其中 `ok=true` 且有赛事的系列。

赛事详情页也请求 `/api/schedule`，再找匹配 ID；其请求不复用首页的 localStorage fetcher。

## 2. `/api/schedule` 编排

1. 初始化相关表，并行读取三个系列最近成功快照。
2. 已有快照立即返回，不等待上游抓取。超过一小时的快照通过 Next.js after() 在响应后更新；同一函数实例内合并重复更新。不同实例仍可能各自更新。
3. 没有快照的系列才在请求内抓取，F1/FE 受每日配额限制；WRC 官网抓取仍允许，第三方回退受配额限制。首次无快照仍可能较慢。
4. 后台更新遵循原有失败回退、成功保存和配额规则；失败不会覆盖有效快照。快照尚未更新时继续显示旧数据。
5. 人工覆盖使用一次 getAllOverrides 查询后按事件 ID 合并，保持顶层浅合并和 F1 图片匹配行为。
6. 返回 events、sources、生成响应时间 fetchedAt；sources.note 包含快照时间。

首页挂载后从 localStorage 恢复各系列最近成功的赛历，在网络更新期间继续显示；缓存不意味着处于离线模式。来源栏会用琥珀色标记本机缓存数据，鼠标悬浮可查看上次成功时间和当前请求结果。后台编辑后的最新覆盖在下一次接口读取时生效。浏览器缓存仅在本机保存；服务端数据库快照和此缓存相互独立。

`refreshSeries` 使用共用 `fetchWithSnapshot`：上游抛异常、返回 ok=false 或成功空列表时，读取最近成功快照；没有可用快照时保留失败结果（WRC 可含估计数据）。失败结果不写入快照，也不增加计数。新数据获取成功但数据库保存失败时显式标记 persistenceError，后台不会假报持久化成功。

## 3. F1

实现：`lib/fetchers.ts:fetchF1`。

- 按服务器当前年份并行请求 Jolpica 的当前年、后两年赛历，以及上一年赛果；赛历每小时重新验证。当前年赛历失败视为整体失败，尚未发布的未来赛季（例如 HTTP 404）跳过，返回的空赛季不影响其他年份。
- 当前赛历负责赛事和练习、冲刺排位、冲刺、排位、正赛时间；缺少日期或时间的场次被跳过，不估计补齐。
- 日期和带 Z 的时间组合为 UTC ISO，场次按时间排序。ID 为 `f1-{season}-{round}`。
- 上年结果按 circuitId 匹配，用第一个结果补充上年冠军与该车手的 FastestLap；不保证是整场比赛最快圈。赛事 ID 含官方赛季年份和轮次，未来赛季发布后可自动加入。
- 中文名、国家、时区、地区、赛道类型、赛道长度/圈数、本地图片和五星体育说明来自代码映射，不是实时爬取。
- Jolpica 当前赛季请求失败时尝试回退到 F1 官网公开赛历；官方只公布日期时不伪造场次时间。两路都失败才返回空列表；官网日历页按小时缓存。

## 4. Formula E

实现：`lib/fetchers.ts:fetchFe`。基础地址是 `https://api.formula-e.pulselive.com/formula-e/v1`。

1. `/championships` 选择当前、Future/Upcoming 且赛季年份未过期的赛季。
2. 并行请求这些赛季的 `/races?championshipId=...`，合并已发布的赛事；ID 使用官方 race ID，避免跨年度重复轮次冲突。
3. 并行请求每场 `/races/{id}/sessions`。以上请求的 fetch revalidate 均为 3600 秒；赛季列表或未来赛历尚未发布时保留当前可用年份。
4. 保留 Free Practice、Qual Group A、Race，分别显示练习、排位、正赛。其他排位分组/淘汰赛场次不显示。
5. UTC = 当地日期时间减 `offsetGMT` 分钟；展示时区用整点 `Etc/GMT`，半小时时区回退 UTC，但保存时间仍使用分钟偏移。
6. 没拿到可用场次但有比赛日期时，Pulselive 会补当天 UTC 12:00 的正赛并标记 `tentative=true`；官网日期回退只补日期，不把占位时间当作开赛时间。单场抛异常则该赛事被过滤掉，其他场仍可返回整体 `ok=true`。
7. ID 为 `fe-{raceId}`；中文国家、地区、街道赛道描述和转播说明来自本地映射。

## 5. WRC 多级获取

实现：`lib/wrc-puppeteer.ts:fetchWrc`。文件名虽然包含 Puppeteer，当前依赖及实现没有启动 Puppeteer。

先根据服务器当前年份检查当前年和下一年的 WRC 官方 Event Series 页面；从赛事页预渲染缓存发现各年 series ID，再请求官网 GraphQL 目录和赛事卡片。公布的未来赛事会按“年份 + 轮次”生成新事件，不再局限于本地已有轮次。2026 的本地 14 场资料仅作官方目录暂不可用时的兼容回退，提供中文信息、坐标等。新年度未有行程时按日期生成待确认估算场次；官方赛段时间尚未公布时不展示成已确认时间，也不请求第三方补未来赛季时间。

## 当前年与下一年赛历自动补齐

- `lib/official-calendar-scrapers.ts` 不使用 API Key，读取 F1 官网按年份的公开赛历页，以及 Formula E 官网公开赛历页；前者逐年请求当前年和下一年，后者解析跨自然年的赛季轮次。
- 抓取只把官网公布的赛事日期和轮次作为事实。缺失具体练习、排位或正赛时间时，只生成标记待确认的日期条目；首页卡片显示当地日期和“时间待确认”，不启动倒计时、不显示 LIVE，也不允许按未确认时间设提醒或导出 iCal。
- `lib/fetchers.ts` 在 Jolpica / Pulselive 缺少未来轮次时用官方日期补齐，并继续优先保留 API 的已确认场次时间。WRC 官网 GraphQL 目录按当前年及未来两年发现轮次。
- `/api/schedule` 保持最近快照立即响应，不为未来日期补齐额外等待官网请求；2027 已公布赛历另有本地应急日期表。未来年份由每小时缓存的官网抓取和既有过期快照后台刷新机制自动滚动，未发布的年份不会编造赛事。
- 这些上游网站没有承诺为第三方提供稳定的日历 API；网页结构、访问策略或未来赛历发布时间变化时，抓取器可能需要适配。Jolpica 和 Pulselive 仍是公开无 Key 的接口，官网抓取用于补全公开日期。

行程会提前检查当前年及未来两年的全部已发现赛事，不再等到未来赛事开赛前 45 天才尝试。官方尚未发布行程时保留标记为待确认的兼容场次；后续访问触发刷新时会再次抓取，官网有效行程成功后替换待确认时间。已存在同日期和 slug 的待确认事件不能跳过官网刷新。未来年份不调用额度受限的第三方回退。官方日历为部分赛季时，仍保留对应年份的本地已知轮次；重复、其他年份或不完整条目不能覆盖目标。未来赛季不再因轮次相同而覆盖当前赛季。

每场官网行程按以下次序尝试：

0. 先读取赛事官网页面，发现 itinerary URL（无法发现时使用标准路径），读取并解析行程 HTML / 预渲染缓存。成功获得有效场次就直接返回，不调用 feed 回退。页面访问失败或没有可用赛段时间，才进入以下回退链路；feed 为最高优先级。

1. 并行尝试四种 itinerary slug，请求官方 feed 的 `event-details` / `inlineContent`。解析 FAQ 中的日期和赛段时间。
2. 全部失败时读取 mainSubPage 补充信息用于日志，然后进入旧链路。
3. 获取赛事首页 HTML：直接请求 → `_escaped_fragment_=` 页面 → PhantomJsCloud 渲染服务。
4. 提取 HTML 的 `rb3-prerender-data-cache`，从 pageTabs 发现 itinerary slug；发现失败时再尝试常见 slug。
5. 请求发现的 itinerary Feed API。
6. 仍失败则请求 itinerary 的 `_escaped_fragment_=` 页面，解析预渲染 JSON 或 HTML。
7. 仍失败且首页存在预渲染缓存时，尝试 itinerary / results 页面，直接请求或 PhantomJsCloud 渲染，再解析 JSON 或 HTML。

官网明确声明 UTC/GMT 偏移时按声明转换，否则使用赛事 IANA 时区。Power Stage 标为主场次，成功合并同步赛事 tz。

如果配置 `OCBLACKTOP_API_KEY` 且允许回退，在首次官网行程失败后按需获取共享的 ocblacktop rally 索引。官网每场失败后按赛事信息匹配索引，请求详细赛段并转换时间，第三方成功事件依然标记 `tentative=true`。

全部目标以最多 4 场并发处理，单场失败不影响其他场结果顺序。第三方赛事索引仅在官网行程失败后按需获取，一次完整更新共享同一索引 Promise。配额不允许时不请求第三方索引或详情。取消失败赛事整条多级链路的第二轮重跑；普通 HTML 网络请求自身仍保留短暂故障重试。

成功场次替换基础估计场次并同步 slug / 官方计时链接；失败场保留估计数据。至少一场官网或 ocblacktop 成功就返回整体 `ok=true`，所以成功状态不代表全赛季真实数据。`dataSource` 是 scraped / api / mixed，note 描述成功和估计场数。官网全失败时返回完整估计列表、`ok=false`。

普通 HTML 请求每次超时 15 秒、最多三次尝试；不同 API 有各自超时。PhantomJsCloud 请求现有 12 秒 AbortSignal 超时。完整赛季限制 4 场并发，但多级回退单次更新仍可能耗时较长。一次 WRC 更新共享 180 秒总网络预算，HTML、feed、辅助 API、渲染和第三方请求均使用该取消信号；到期停止新请求并取消未完成网络请求，保留已获取结果。不同抓取通过 AsyncLocalStorage 隔离预算。主赛历接口声明 `maxDuration=300`，实际部署允许时长尚未验证。

定义的 EventHero / iCal 辅助函数目前没有接入主获取链路，不能当成已使用的数据来源。

## 6. 缓存、数据库与刷新入口

- Neon PostgreSQL：通过服务端 `DATABASE_URL` 连接。快照是追加 JSONB 记录，过滤 ok=true 且非空 events 后按 fetched_at 取最新成功记录，没有快照年龄上限或自动清理。
- 配额查询与递增分开，没有原子预留，并发可能超过 10 次。无数据库时快照/覆盖不可用，计数不持久化。
- 自动刷新由 `/api/schedule` 的访问触发，不配置 Vercel Cron：有持久化快照时，快照超过一小时后在响应后更新；F1 / FE 每个系列每日最多成功保存 10 次，达到上限后跳过自动更新；WRC 官方赛历按访问刷新，使用 ocblacktop 回退时受每日配额控制。无人访问期间不会主动更新。F1 / FE 上游 fetch 显式缓存一小时；WRC 请求没有同样的显式一小时 fetch 设置。实际响应缓存行为应在部署环境核对。
- 首页 SWR 内存缓存；失败时 localStorage 离线回退，没有缓存年龄上限。
- 生产环境注册 `public/sw.js`：GET API 网络优先，网络异常时读取 Cache Storage；页面/静态资源缓存优先。只缓存成功且没有 no-store 的 API 响应；管理页面、管理接口和反馈接口不缓存。缓存版本已更新以清除旧缓存。
- 按用户选择移除 Vercel Cron，不配置独立定时任务。用户访问首页或赛事详情时，客户端请求 `/api/schedule`；服务器先返回成功快照，过期超过一小时才通过 `after()` 后台抓取并保存。没有访客时不会运行；构建也不会爬取。HTTP 200 只代表响应成功，不能证明后台抓取或数据库写入成功。
- 新增公开页面客户端辅助采集：使用访客网络直接请求公开 F1 / 单场 WRC 接口，回传服务端后按稳定 ID 和场次自动补缺。有效现有时间不覆盖，采用内容保留客户端来源与待核验标记，首页 EventCard 的小 `i` 展示详情。全站每系列每三小时最多分配一次，数据库事务保存正式快照与任务记录，不需要人工审批。CORS、暂停条件与持久化细节见 [客户端采集说明](client-crawl.md)。

后台入口：

- `/api/admin/crawl` POST：要求有效签名会话与数据库，调用与首页相同的 refreshSeries。F1 / FE 配额耗尽阻止刷新，WRC 仍允许官网获取但关闭第三方回退。仅成功非空结果保存和计数，失败返回 502 并保留已有成功快照。
- `/api/admin/status` GET：要求有效签名会话，仅读取各系列最近成功快照。状态不代表实时上游连通性；加载后台不再抓取全赛季，也不写新的健康检查历史。
- `/api/admin/snapshot`：查看原始快照；`/api/admin/overrides`：管理人工覆盖；`/api/admin/preview`：预览快照加覆盖。预览现已使用 `snapshot.data.events`，与持久化结构一致。

新增数据库检查入口：GET /api/admin/database。仅检查白名单中的九张应用业务表（含 `client_crawl_jobs`），显示表是否存在、字段类型、可空性、选中表的准确记录数与分页记录；稳定主键排序，无主键时按 ctid 排序。表名使用白名单，分页值参数化，推送凭据、地址和任务 token 哈希隐藏，大字段截断到 16,000 字符，响应不缓存。此功能不创建表、不执行任意 SQL，也不提供数据修改或删除。

管理员登录继续使用 ADMIN_PASSWORD；服务端签发随机、签名的一小时 cookie，HttpOnly / SameSite=Strict / 生产 Secure。修改密码后旧会话无效；写操作检查来源，退出通过服务端 DELETE 清除 HttpOnly cookie。旧 true cookie 不能登录。

## 7. 其他数据链路

| 功能 | 当前来源与处理 |
| --- | --- |
| F1 赛果 | `/api/results` 请求 Jolpica `/{season}/results.json?limit=1000`，缓存一小时；首页上一场赛果直接从浏览器请求 current/last/results.json。 |
| FE 赛果 | `/api/results` 从 championships 匹配赛季，再取 races，逐场顺序请求 results，单场失败跳过，缓存一小时。 |
| F1 积分榜 | `/standings` 页面经 `/api/f1-standings` 服务端请求 Jolpica current/driverStandings 或 constructorStandings；单次上游超时 10 秒，成功缓存一小时，失败可重试，不使用 Neon。 |
| WRC 积分榜 | `/standings` 经 `/api/wrc-standings` 服务端读取 WRC 官网公开端点。页面源码加载 `p-p.redbull.com/rb-wrccom-lintegration-yv-prod/api/seasons.json`，按赛季读取 `season-detail.json?seasonId=…` 获取各分类 `championshipId`，再合并 `championship-detail.json?championshipId=…&seasonId=…` 的参赛者资料与 `championship-overall-results.json?championshipId=…&seasonId=…` 的积分、名次。整条上游请求链共享 9 秒超时，超时返回 502 且不缓存失败结果；成功响应由服务端与 CDN 缓存一小时。页面可切换赛季及车手、领航员、制造商等分类。该端点为官网前端使用的非公开文档 API，格式或访问策略变化时可能需要调整。 |
| FE 积分榜 | `/api/fe-drivers` 读取 Formula E 官网公开积分榜；默认使用官网当前赛季，也可通过 `season` 参数读取赛事对应的历史/指定赛季。页面 HTML 结构变化或上游不可用时返回 502。 |
| WRC 赛果 | 暂无完整赛果获取链路；积分榜已接入 WRC 官网公开接口。实时计时链接仍供用户前往官网查看。 |
| F1 实时计时 | 展开组件请求 `/api/live-timing`，每次请求结束后再计时刷新，避免请求慢时重叠；收起组件会取消浏览器请求。服务端用同一个 8 秒截止时间访问 OpenF1：获取本年度 sessions，找到当前场次后并行请求 drivers、position、laps、intervals、pit、race_control。名次、圈速、圈差和进站次数来自对应上游字段，不再按名次伪造差距或用 `0` 冒充缺失数据；车手退赛状态当前无法从实时源可靠确定，显示未确认。旗帜/安全车状态按最新 race control 消息归纳，源不可用时保持未知。成功数据 CDN 缓存 5 秒并可后台保留旧响应 10 秒；无活动场次的 404 缓存 30 秒并提示客户端 30 秒后重试。[OpenF1 文档说明其实时数据需要付费订阅](https://openf1.org/docs/)，当前部署未配置其认证，因此实时阶段可能只能显示官方页面回退。 |
| WRC / FE 实时计时 | API 返回空 drivers 的官方来源占位对象。WRC 前端不轮询，直接引导官网；FE 组件仍有 10 秒轮询，但没有真实计时数据接入。 |
| 天气 | `/api/weather` 优先用经纬度，否则 Open-Meteo 地理编码、再本地城市坐标回退；查询目标日期前后三天 daily forecast，地理编码缓存一天、天气缓存一小时；日期范围限制及重试在该路由实现。 |
| 图片 | F1 赛道图为 public 本地资源；WikipediaImage 浏览器请求 Wikipedia REST summary；image-proxy 仅代理 `upload.wikimedia.org`、`thumb.wikimedia.org` 与 `en.wikipedia.org` 的 HTTPS 图片，仅返回 AVIF/GIF/JPEG/PNG/WebP 等栅格图片，拒绝可执行 SVG 和其他内容类型；最多跟随 3 次同名单允许重定向，10 秒超时并限制响应体为 8 MiB；成功响应共享缓存一天并允许过期内容最多 stale 7 天，异常响应不缓存。 |
| AI 预测 | POST `/api/predictions` 在数据库中原子占用每日额度后请求 NVIDIA NIM Llama 3.1 8B，输入赛事系列、名称和赛道，未实际加载历史成绩/天气进行分析；额度耗尽、数据库额度无法核验或服务 HTTP 失败时返回本地默认预测。额度按已发起的上游请求计数，失败请求也占用额度；无 `DATABASE_URL` 时额度无法持久化。 |
| 投票/反馈 | predictions 的 GET 统计数据库投票并按匿名浏览器身份读取本人选择；POST 带 driverCode 时写投票。同一浏览器使用一年期 HttpOnly、SameSite=Lax 随机 cookie，在同一赛事内重复提交会更新而非重复计数；清除 cookie 或更换浏览器会被视为新匿名用户，不是防作弊身份认证。车手候选按赛事赛季动态读取，F1 使用 Jolpica 车手积分榜，WRC 使用官网车手积分榜，FE 使用官网车手积分榜；历史投票代码仍显示原标签。反馈通过 `/api/feedback` 写入/读取 Neon。它们不属于赛历上游抓取。 |

## 9. WRC 时间可信度与显示

日历壁纸页仅从 `/api/schedule` 读取实际返回的赛程，加载中显示等待状态、请求失败显示错误，不再用虚构赛程填充。手机按月、桌面按年，在浏览器生成 PNG，不写数据库。赛事按主场次的北京时间日期分组，统计、跨月跨年归属与时间显示统一使用 Asia/Shanghai；手机壁纸中的估计 WRC 时间只显示“待确认”。详情页另有主场次 ICS 下载，按 UTC 导出，不与壁纸 PNG 混用。

估计 UTC 保留在数据契约中。详情、EventCard 展开内容和分享卡片显示“时间待确认”，不显示具体估计时间，也不生成精确倒计时、赛段天气、日历导出或提醒。场次 tentative 优先于赛事 tentative；明确 false 的场次仍显示确认时间，缺失时继承赛事标记。F1/FE 不受影响。

官网页面缓存与 Feed 共用 parseItineraryItems。日期支持 ISO、英文月份、序数词和显式年份；验证实际日历日期、小时 0–23、分钟 0–59、名称和 UTC/GMT 偏移，过滤重复场次。无效 FAQ 版本、空节点、错误字段和非数组列表不会阻止继续寻找有效版本；不会混合多个行程版本。有效官网场次明确标记 tentative=false。

FAQ 与普通 HTML 共用赛季归属检查。显式年份属于其他赛季时排除，但允许与赛事首日相差不超过七天的跨年日期。普通 HTML 必须有明确日期分区，不能把散落时间套到赛事首日冒充确认时间。FAQ 标题或 HTML 日期分区声明 UTC/GMT 时使用明确偏移；没有声明时使用赛事 IANA 时区，非法偏移不回落当地时区。

第三方索引用官方 eventSlug 匹配英文赛事名，拒绝空名称、仅 WRC/Rally 等通用词、其他赛季和多候选歧义。提供起始日期时须在目标日期前后七天内。时间区分明确 UTC 字段、带偏移 ISO 和当地墙上时间，不依赖服务器当地时区；显式偏移最大 ±14:00，保留秒和毫秒。

## 10. WRC 调度、请求复用与解析入口

先抓取最近五天开始的赛事，再抓未来十四天、过去十四天，其余按距当前日期排序。只改变请求顺序，输出仍按基础事件 ID 与轮次合并。总预算到期的排队任务跳过，不重启完整回退链。所有候选必须转换出有效赛段才算成功，包括 Feed、SSR 和旧 HTML 多页面回退。

单次抓取内使用 AsyncLocalStorage 共享已解析 Feed/JSON、成功 HTML 正文及进行中的 Promise。Feed 键含 slug 和用于解析年份的日期；JSON/HTML 键含完整 URL。消费者取得深拷贝；null 和异常不保留，不同抓取不共享。跨请求回退由数据库快照承担。

HTML 正文读取中断进入有限重试，403 等非 5xx 失败不重试。统一请求层取消非成功 HTTP 响应的未使用正文，清理异常不覆盖原始状态，成功正文仍可读取。

预渲染 script 提取支持属性换序、单/双引号、大小写和额外属性，仅匹配实际 id；数据必须为 JSON 对象。损坏候选继续查找后续缓存。页面发现的链接按 URL 解析，接受 HTTPS www.wrc.com 下本场路径的绝对或根相对地址；Results 查询参数合并，Feed slug 只取路径末段，不含查询或锚点。

官方目录验证 events 数组、去重字符串 ID，赛事卡片最多四个并发且隔离失败；校验 round、slug、日期、标题类型。部分目录保留全部已知本地轮次，未知/重复/其他赛季目标不覆盖。两份本地起始日期的对齐仅证明内部一致，不代表重新核实官方最新赛历。

## 11. WRC 历史快照与诊断

成功保存前按同一事件 ID 合并历史确认时间。整场回退到估计且旧快照全部确认时保留旧赛段；混合结果按 SS 编号、Shakedown 或规范名称恢复唯一匹配的确认场次，新确认时间优先。历史估计、无效时间或歧义匹配不会升级为确认。合并后重算待确认赛事数，来源说明标注保留历史赛段数。数据库写入失败由调用方处理，不重复插入。

抓取结果 diagnostics 随成功快照保存；只含计数和耗时，不含 URL、密钥、请求头或正文：

| 字段 | 含义 |
| --- | --- |
| requests | 实际网络请求次数 |
| networkFailures | 收到 HTTP 响应前的网络失败；不含 HTTP 错误、正文读取或解析失败 |
| httpStatuses | 收到的 HTTP 状态码计数 |
| cacheHits | 本次解析数据或 HTML 正文的缓存复用次数 |
| durationMs | 当前抓取总耗时 |
| budgetExpired | 180 秒预算是否已耗尽 |

后台手动抓取成功响应的 data 和失败响应顶层都提供本次诊断。回退旧快照时保留历史快照诊断，并单独提供当前尝试诊断，避免混淆。失败不生成成功快照。爬虫管理页显示本次计数、状态、耗时；新一轮 WRC 抓取、退出登录或刷新清除展示。

验证使用固定本地 HTTP 响应，覆盖官网 HTML、HTML 失败后的 Feed 优先回退、UTC 解析、稳定 ID、部分估计、无效候选、坏字段、年份、缓存隔离和快照保护，不连接生产数据库或消耗第三方额度。2026-10-11 已能进行部署页面浏览器 QA，结果见 `docs/qa-2026-10-11.md`；本地测试及部署状态不代替线上页面验证。

## 12. v2.2.2 赛果、积分与展示修正

- F1 赛果使用 Jolpica `limit=100&offset=...`，按实际返回的结果行数推进，并检查 `total/offset`。同站成绩可跨页，按赛季、轮次及名次合并，不截断到 20 名。任一页失败或空页提前终止时返回失败，不能把部分赛季标为完整。去年冠军资料也使用同一分页函数。单页超时 10 秒，成功响应交由 Next fetch 缓存一小时。
- FE 积分和赛果读取 [官网公开页面](https://www.fiaformulae.com/en/results-and-standings)，不再依赖不可达的旧 PulseLive 积分/赛果接口。积分取 `standings-row-driver` 的总积分列；赛果取 `results-row-result`，保留未分类的“—”。赛历只解析 RSC 中的 JSON 轮次目录，不执行脚本；赛季结束年份减 2014 得到官方赛季编号，并校验页面实际选中的赛季编号和轮次。官网历史页的 SEO 标题可能保留当前赛季，不能用标题判断数据归属。
- FE 历史页面先读取赛历和官网默认选中站成绩，其他单站成绩仅在用户展开时读取；新查询接受白名单格式的赛季及已知轮次 ID。每个上游请求 10 秒超时、成功页面缓存一小时；解析失败为 502、中文提示及重试，失败响应禁止缓存。积分/赛果没有新增 Neon 持久化，不应与赛历快照混为一谈；FE 赛历原有链路保持原状。官网 HTML 结构变化仍可能导致解析失败。
- 赛事投票候选按赛事赛季动态读取：F1 从赛事 ID 解析年份并读取 Jolpica 积分榜，WRC 解析年份并读取 WRC 官网车手积分榜，FE 从官方赛事 ID 解析赛季号并读取 Formula E 官网积分榜。SWR 按接口 URL 复用名单；候选代表赛季积分参与者，不保证未来每站的最终参赛名单。FE/WRC 旧投票代码仍以历史标签显示；提交失败时恢复用户之前的选择，切换赛事时清空前一场的投票状态。
- 返回赛历前修正已有快照中的拉斯维加斯街道分类、2026 新加坡赛道长度和新增中文名称，然后应用人工覆盖；不写回快照、不改事件 ID 或场次 UTC，人工覆盖仍优先。
- 周编号使用北京时间的 ISO 周年及周数；跨年周从 1 月 4 日所在周计算。月历计数明确是赛事日条目，并非自由练习/排位/正赛总场次数。
- 日历导出加入稳定 UID、DTSTAMP、UTC 起止、文本转义和 UTF-8 75 字节折行；估计主场次及无效 UTC 不能导出。日历经无状态 `/api/calendar` 返回附件，校验参数，不读取或写入数据库、不触发抓取；客户端仅导出已确认主场次。下载 anchor 加入 document，图片 Blob URL 延迟一分钟回收。该修正改善兼容性，但是否能落盘仍需实际浏览器验证。
- Service Worker 缓存版本提升至 `race-calendar-v2.2.2`，利用已有激活流程淘汰旧版本资源缓存；指南已读标记和用户投票不清除。

## 13. F1 积分榜请求

积分榜页的 F1 车手和车队数据由 `/api/f1-standings` 服务端适配 Jolpica API。浏览器不再直接连接第三方；接口只接受 `drivers` / `constructors` 两种类别，默认读取当前赛季，设置单次 10 秒上游超时，成功数据缓存一小时并允许 CDN 在缓存失效时提供旧响应一天。上游失败或结构异常返回不缓存的 502，页面提供重试；切换车手/车队标签会取消前一个浏览器请求，避免迟到响应覆盖当前状态。接口成功但积分榜为空时显示“官方暂未提供”提示，而非空白图表。WRC 和 FE 积分榜仍使用各自既有链路。

## 14. 浏览器同站资源适配与境内访问

- 旧版和新版的上一站 F1 赛果统一请求 /api/f1-last-result；服务端只访问固定 Jolpica current/last 路径，10 秒超时、成功缓存 5 分钟，失败或无有效赛果返回不缓存的 502，不连接数据库。浏览器不再依赖直接连接 Jolpica。
- 维基参考图片摘要通过 /api/wiki-summary?title=... 请求；仅允许固定 Wikipedia summary 路径和长度受限的编码标题，上游不跟随重定向。仅返回 Wikimedia 白名单图片元数据；图片仍经已有 /api/image-proxy 获取。8 秒超时，成功缓存一天，失败显示原有占位内容，不阻塞页面。
- 正式域名为 https://race.huosai.ccwu.cc/；racebeta.huosai.ccwu.cc 和 racecalendar-visualize.vercel.app 绑定开发分支。字体由 next/font 在构建时打包，浏览器使用本站静态字体；核心赛程、积分榜、天气和投票使用本站接口。客户端辅助采集仍是可失败的后台增强，不是打开网站的前置条件。
- 同站适配减少访客跨境依赖，但无法保证所有运营商到 Vercel 的线路质量。绕过显式终端代理收到 HTTP 200 只证明该请求路径可用，不能代替境内手机、Wi-Fi 和蜂窝网络实测；多地区 HTTP 节点结果也不能证明所有交互均可用。
- 浏览器请求超时使用 `lib/browser-abort.ts` 的 AbortController 定时取消，不依赖旧版 Safari / 微信 WebView 可能缺少的 AbortSignal.timeout/any。辅助采集继续继承页面取消信号；超时不改变补缺和持久化策略。弹窗焦点陷阱在缺少 checkVisibility 时检查布局及关闭的 details，避免打开弹窗直接抛出异常。此兼容修复不能解决 DNS/TLS 连接失败，仍需实际设备验收。
