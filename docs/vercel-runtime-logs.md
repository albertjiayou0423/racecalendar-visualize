# Vercel 运行日志

服务端 API 使用单行 JSON 结构化日志。部署后在 Vercel 项目的 **Logs → Runtime Logs** 中搜索 `event` 字段，即可按事件定位错误；每条日志包含 UTC 时间、级别和少量上下文。

常用事件：

- `api.schedule.*`：赛历数据库初始化、快照读取、上游数据不可用、配额检查和后台刷新。
- `api.predictions.*`：预测投票读取/提交、AI 上游失败和候选处理。
- `api.weather.*`：天气服务重试、地理编码失败和上游错误。
- `api.*.fetch_failed`：赛果、车手名单和积分榜上游获取失败。
- `api.client_crawl.*`：客户端补充采集接口的数据库或任务失败。

日志不会记录请求正文、投票者标识、完整 URL、坐标或凭据。新增服务端日志时使用 `lib/server-log.ts`，只传必要的状态码、系列、阶段等低敏上下文，不要直接输出请求对象、响应正文或密钥。

## 邮件通知

- `RESEND_API_KEY`、`RESEND_FROM_EMAIL`、`ALERT_MAIL_TO` 仅由服务端读取；API Key 不得进入客户端代码。
- 项目不使用 Cron。每次有用户请求 `/api/schedule` 时，服务端记录 F1、FE、WRC 的可用性；若三者同时失败，会尝试发送故障邮件，同类事件由数据库限制为最多每 6 小时一次。
- 月报在当月首次成功执行赛历接口的请求后，发送上一个完整自然月的采样摘要；数据库以月份作为唯一键，避免重复发送。没有访问时不会准点发送，之后有访问才补发。
- 数据库初始化失败会在该次赛历请求后尝试发告警；浏览器在赛历请求失败且本机也没有可用缓存时，会报告一个固定的失败类型。每个浏览器标签页最多每 10 分钟报告一次；数据库按 10 分钟窗口计数，达到 5 次后发邮件，并将同类提醒限制为每 6 小时一次。
- 客户端报告不包含网址、错误堆栈、用户标识或请求正文，只用于聚合赛历加载失败次数；它依赖页面和 API 仍可访问。如果整个域名或网络不可达，浏览器无法上报。
- 这些记录是访客请求时的采样，不是持续探活或完整 uptime 监控；数据库可以聚合与去重，但不能在没有请求时唤醒服务或按时发送邮件。没有访客时，月报和新故障告警会延后。
- 后台“邮件通知”页会显示环境变量是否齐全、近 30 天赛历采样、邮件接受记录、故障去重状态和月报状态；管理员可手动发测试邮件到 `ALERT_MAIL_TO`，一分钟限发一次。Resend 返回接受只说明服务商接收了请求，不保证最终送达。
- 测试邮件 API 为 `POST /api/admin/notifications`，仅限已登录管理员并校验同源；监控 API 不返回密钥或收件地址。测试发送本身会记入 `notification_email_log`。
